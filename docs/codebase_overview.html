Codebase Overview

ICRA Vision Module: perception 결과가 grasp point와 robot target으로 바뀌는 구조

이 문서는 dual RealSense 기반 handover pipeline을 팀/리뷰어가 빠르게 이해하도록 만든 standalone HTML이다. 핵심은 cam0/cam1에서 얻은 object와 hand 정보를 robot base frame으로 통합하고, object geometry와 hand clearance를 기준으로 grasp point를 만든 뒤 UR RTDE follow와 Robotiq grasp까지 연결하는 흐름이다.

Main entry robot_control_rtde_fitting_final.py
Main config configs/handover.yaml
Grasp logic perception/grasp_target.py
Runtime idea measured target, hand fallback, short prediction을 구분해서 follow한다.

System Architecture

데이터가 흐르는 방식

전체 구조는 sensor lane, perception lane, decision lane, execution lane으로 나누어 볼 수 있다. 각 lane은 shared state와 timestamp freshness를 통해 연결되고, 최종 제어 대상은 robot base 좌표계의 control_target_xyz_mm로 정리된다.

Sensor Lane
cam0/cam1

DualSensorHub

system/dual_sensor_hub.py가 두 RealSense의 color/depth frame pair를 만든다.

sync

Frame freshness

max_pair_time_delta_sec와 stale timeout 기준으로 너무 오래된 state를 제외한다.

depth

Depth filtering

카메라별 spatial, temporal, hole filling filter와 optional FDCT depth completion을 적용할 수 있다.

calibration

Transform chain

cam1_to_cam0와 cam0_to_robot_base로 모든 3D point를 robot base frame에 맞춘다.

Perception Lane
object

YOLOE segmentation

SegmentationEngine이 prompt class와 confidence 기준으로 object mask 후보를 만든다.

cloud

Mask to point cloud

mask 내부 depth pixel을 deproject하고 voxel downsample, outlier removal로 object cloud를 만든다.

hand

Hand pose lifting

2D hand landmark를 depth로 3D lifting하고 palm center와 hand pose 품질을 계산한다.

select

Active hand selection

HandSelector가 handover에 사용할 selected hand를 고르고 fusion 단계로 넘긴다.

Decision Lane
fusion

Filtered states

PerceptionFusion이 object centroid와 hand center를 temporal filtering하고 approach state를 만든다.

shape

Template fitting

ShapeFittingTracker가 cup, wine glass template을 point cloud에 맞춰 fitted geometry를 만든다.

grasp

Grasp target

centroid 주변 후보 point 중 hand clearance를 만족하는 후보를 골라 robot base grasp point를 만든다.

robustness

Fallback and prediction

object dropout은 hand-relative fallback으로, 짧은 target dropout은 predictor로 이어받는다.

Execution Lane
target

EEF target

grasp/object point에 EEF offset 또는 dynamic offset을 적용해서 robot control target을 만든다.

follow

RTDE follow

robot_control_loop가 control target을 속도 제한과 workspace clamp 안에서 servo command로 보낸다.

gripper

Direct grasp

EEF와 grasp/object point가 tolerance window 안에 들어오면 follow를 멈추고 gripper close를 실행한다.

records

Metadata and video

geometry, fill, mass, contact timing, delivery location, video recording, debug artifacts를 저장한다.

Runtime Flow

State machine 관점의 실행 흐름

이 pipeline은 단순히 매 frame마다 object를 따라가는 구조가 아니다. 처음에는 안정적인 reference를 lock하고, object가 충분히 움직였을 때만 follow를 시작한다. 이후 target source가 measured, hand fallback, predicted 중 무엇인지에 따라 control target을 선택하고, direct grasp 조건이 만족되면 follow thread에서 gripper close 단계로 handoff한다.

초기화

config, calibration, camera hub, segmentation model, hand workers, fusion, shape fitting, RTDE, gripper, recorder를 준비한다.

Reference lock

object position이 안정적으로 관측되면 REFERENCE_LOCK_COUNT 이후 초기 object 위치를 기준점으로 저장한다.

Motion trigger

object가 초기 위치에서 XY 또는 Z 방향으로 충분히 움직이면 motion_triggered가 true가 되고 follow 준비가 끝난다.

RTDE follow

fresh target, 최소 valid streak, fixed Z/orientation, workspace 조건을 만족할 때 servo command를 연속 전송한다.

Target source 선택

fresh measured target을 우선 사용하고, 없으면 hand fallback 또는 짧은 horizon의 predicted target으로 control target을 유지한다.

Direct grasp trigger

EEF와 grasp/object point의 X, Y, Z 오차가 tolerance 안에 들어오면 follow를 stop하고 gripper close로 넘어간다.

Grasp and place

gripper close 후 contact timing, grasp Z sample, template bottom Z sample을 바탕으로 place 높이를 freeze한다.

Record finalize

return/place, gripper release, metadata completion, video save/discard UI, runtime profile/debug capture가 review evidence가 된다.

Follow가 켜지는 조건

  • follow_enabled가 true이고 follow pause 요청이 없어야 한다.
  • motion_triggered가 true여야 한다.
  • control_target_xyz_mm가 존재해야 한다.
  • measured target이면 min_valid_count 이상이거나 prediction이 armed 상태여야 한다.
  • fixed_z_mm와 fixed_orientation_base가 설정되어야 한다.

Follow가 멈추는 조건

  • target이 timeout되었고 valid prediction도 없으면 inactive가 된다.
  • predicted target의 prediction_age_s가 horizon을 넘으면 사용하지 않는다.
  • task state가 FOLLOW가 아니면 prediction과 follow target을 reset한다.
  • direct grasp trigger가 발생하면 follow thread를 release하고 gripper close로 넘긴다.

Grasp Point Generation

Grasp point는 어떤 기준으로 만들어지는가

perception/grasp_target.py의 GraspTargetPlanner는 object point cloud 전체에서 아무 점이나 잡지 않는다. filtered object centroid와 selected hand center를 기준으로 후보를 줄이고, hand와 충분히 떨어져 있으면서 object 중심에 가까운 후보를 고른다. 최종 grasp point는 안정성을 위해 XY를 object centroid에 고정하고, Z만 선택된 후보 point의 높이를 사용한다.

1 input

입력 state 확인

merged/fitted object가 valid이고 selected hand의 palm center가 있어야 한다. 없으면 invalid 또는 이전 target hold로 간다.

2 candidates

Finite point 후보

merged_points_base에서 NaN/Inf가 없는 3D point만 raw candidate로 사용한다.

3 radius

Centroid radius filter

object centroid에서 candidate_search_radius_from_centroid_m 안에 있는 후보를 우선 사용한다. 없으면 전체 후보로 fallback한다.

4 clearance

Hand clearance filter

height axis에서 hand center와 후보 point의 차이가 min_hand_height_clearance_m 이상인 후보만 남긴다.

5 select

Score and lock

centroid에 가까운 후보를 선호하고, 이전 후보와 멀리 떨어진 후보에는 penalty를 준 뒤 최종 grasp point를 만든다.

object_centroid = filtered_object_centroid_base or merged_object.centroid_base
hand_center = filtered_hand_center_base or selected_hand.palm_center_base
selected_candidate = best finite object point after radius and clearance filters
grasp_point_base = [object_centroid.x, object_centroid.y, selected_candidate.z]

왜 XY를 centroid에 lock하는가

point cloud의 표면 후보는 frame마다 조금 흔들릴 수 있다. 그래서 XY는 object 중심을 따라가게 하고, 실제 grasp 높이만 후보 point의 Z로 가져와 target이 좌우로 튀는 현상을 줄인다.

왜 hand clearance가 필요한가

hand와 너무 가까운 높이의 point를 잡으면 사용자의 손이나 손가락 쪽으로 접근할 수 있다. height axis 기준 최소 간격을 둬서 손과 분리된 object surface 후보를 고른다.

Parameter Current value/source Meaning
candidate_search_radius_from_centroid_m 0.11 in configs/handover.yaml object centroid 주변에서 grasp 후보 point를 찾는 반경이다.
min_hand_height_clearance_m 0.05 in configs/handover.yaml hand center와 grasp 후보 사이에 필요한 height-axis 최소 거리다.
switch_margin 0.01 in target_selection 새 후보가 기존 후보보다 충분히 좋아야 target 전환을 허용한다.
hold_frames 6 in target_selection 비슷한 score 상황에서 기존 후보를 유지할 최대 frame 수다.
dropout_hold_frames 8 in target_selection 후보가 잠깐 사라졌을 때 이전 grasp point를 유지할 frame 수다.
GRASP_POINT_Y_OFFSET_MM 10.0 in robot_control_rtde_fitting_final.py planner가 만든 grasp point에 robot base Y 방향 offset을 추가하는 후처리 값이다.

Measured, fallback, predicted target의 차이

measured

정상 측정 target

segmentation, point cloud, fusion, grasp planner가 모두 유효할 때 사용하는 기본 target이다. predictor update도 measured target에서만 수행된다.

hand_fallback

Hand-relative fallback

object 측정이 끊겼지만 hand/object 상대 위치가 lock되어 있으면 hand 움직임 기준으로 object와 grasp position을 유지한다.

predicted

Short-horizon prediction

TargetPredictor가 짧은 dropout 동안 control target을 예측한다. horizon이 지나면 기존 안전 정지 로직으로 돌아간다.

Code Map

주요 Subsystem

아래 경로들은 현재 handover runtime을 이해할 때 먼저 봐야 하는 기준점이다. 전체 구현은 큰 top-level loop 하나와, sensor, perception, robot, utility module들이 조립되는 형태다.

Path Role Key Idea
robot_control_rtde_fitting_final.py Top-level runtime loop camera, perception, grasp planning, robot control, metadata, video, keyboard control을 통합한다.
configs/handover.yaml Runtime configuration camera serial, calibration file, perception threshold, shape fitting, grasp, robot, safety 설정을 담는다.
perception/grasp_target.py Grasp target planner object centroid, hand center, point cloud 후보, temporal hold를 사용해 robot base grasp point를 만든다.
system/ Shared state and sensor hubs dual sensor snapshot과 perception/control 사이에서 공유되는 typed state를 관리한다.
perception/ Perception pipeline object worker, hand worker, fusion, hand selection, shape fitting, fill estimation, target prediction을 포함한다.
object_pt_extraction/ Segmentation and point clouds YOLOE segmentation 결과를 depth와 결합해 robot control에 쓸 3D object cloud로 바꾼다.
robot/ Robot and gripper control UR RTDE command와 Robotiq gripper interface를 제공한다.
utils/ Runtime support RealSense helper, depth lifting, metadata writing, 3D debug recording, preprocessing, runtime profiling을 담당한다.
video_record.py Web-assisted video recorder handover video를 recording, pending save, discard, label 선택 UI로 관리한다.
FDCT/ Optional depth completion transparent object depth completion model asset과 inference support를 둔다.

Configuration Map

설정이 영향을 주는 곳

대부분의 운영 선택은 configs/handover.yaml 또는 CLI override로 결정된다. command는 repository root에서 실행해야 model, calibration, template 상대 경로가 맞게 해석된다.

Cameras

cameras는 RealSense serial, resolution, FPS, depth filter를 정의한다.

Calibration

calibration.chain은 camera_parameters/c0_to_robot.pckl와 camera_parameters/rot_trans_c1.dat를 참조한다.

Perception

perception은 synchronization, FDCT, segmentation, point-cloud filtering, fusion, fitting, fill estimation을 제어한다.

Grasp

grasp는 fixed orientation, 후보 radius, hand clearance, fallback, temporal target selection을 정한다.

Robot

robot은 RTDE 연결, frame mapping, control rate, gripper behavior, grasp verification을 담는다.

Safety and profiling

safety.workspace_bounds_m는 움직임을 clamp하고, runtime profiling은 CPU/RAM/GPU/VRAM/stage timing을 저장한다.

How to Run

실행 방법

Convenience launcher

현재 final pipeline을 실행하는 launcher다.

bash run_fitting_final.sh

Equivalent direct command

CLI option을 바꾸며 실험할 때는 final script를 직접 호출한다.

python robot_control_rtde_fitting_final.py \
  --config configs/handover.yaml \
  --select-mode highest_score \
  --enable-follow \
  --follow-z
Hardware expected

두 대의 RealSense camera, RTDE로 접근 가능한 UR robot, gripper control이 켜진 경우 Robotiq gripper access가 필요하다.

Model assets

YOLOE weight 예시는 yoloe-26l-seg.pt이고, optional FDCT checkpoint는 FDCT/TransCG.tar이다.

Operator controls

OpenCV window key는 f follow toggle, r reset, d debug save, s finalize, q quit이다.

Reviewer Reading Path

리뷰할 때 읽는 순서

빠른 기술 리뷰라면 README.md로 전체 목적을 보고, configs/handover.yaml에서 운영 파라미터를 확인한 뒤, robot_control_rtde_fitting_final.py와 perception/grasp_target.py를 함께 보면 perception 결과가 robot target으로 바뀌는 결정을 추적할 수 있다.

Behavioral contract

robot은 fresh, valid, bounded target에서만 움직이고, task transition이나 prediction horizon 초과 시 target state를 reset해야 한다.
